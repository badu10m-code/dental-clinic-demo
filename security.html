Security & anti-hacking

Security on this site, explained plainly.

Most clinic websites have never thought about this page. We built this one to show what protection looks like, and to be honest about what a demo can and cannot do.

What protects every visitor

  • HTTPS everywhere. All traffic is encrypted in transit. Nothing you type travels in readable form.
  • Content Security Policy. Every page ships a strict CSP that allows scripts only from this site itself. Even if someone found a way to inject code into a page, the browser would refuse to run it.
  • Input sanitisation. Everything typed into the booking form is escaped before it is displayed anywhere. The injection attacks that plague small-business forms have nothing to latch onto.
  • No third-party trackers. No analytics, no ad pixels, no fingerprinting. The only external requests are the two fonts and the map embed.
  • Minimal attack surface. The site is plain HTML, CSS and JavaScript with no server-side code, no database and no admin login exposed on the public site. The commonest ways small business sites get hacked do not exist here.
  • External links hardened. Links leaving the site carry rel="noopener" so they cannot manipulate the page you came from, and the referrer is not leaked.

How the admin panel is protected in the live build

The panel you can open freely here is a demonstration. In the production version the same panel sits behind a secure login with hashed credentials, session expiry, login-rate limiting, and all appointment data held server-side in an encrypted database with daily backups and audit logging.

Why there is no password in this demo: the panel is open on purpose so you can see every screen without setup. Nothing entered in this demo leaves your browser, and the data is sample data, so there is nothing to break into. The notice inside the panel says the same thing.

Honest limits of a static demo

Because the demo stores bookings in your browser only, there is nothing server-side to attack, which makes it safe by construction. That same design would not suit a real clinic's records, which is why the live build replaces it with the encrypted server storage described above. This page will be updated with the production architecture when the clinic goes live.

If something looks wrong

Report anything unusual (a page that looks tampered with, a message claiming to be from us asking for money or OTPs) straight to the clinic number listed in the footer. We will never ask you for an OTP, a UPI PIN, or a card number.
